## Code Style

- Use consistent naming conventions (e.g., camelCase for variables, PascalCase for classes).
- Include docstrings for all public functions and classes.
- Keep functions focused — each function should do one thing well.

## Architecture

- Follow a layered architecture (presentation, business logic, data access).
- Use dependency injection where appropriate.
- Keep modules loosely coupled.

## Documentation

- Update README files when adding new features.
- Include usage examples in documentation.
- Document decisions and trade-offs in code comments where non-obvious.
